# Информационная система сети медицинских клиник

Учебный сквозной проект по курсу «Проектирование и оценка качества программных
систем» (МОМС21, ДГТУ). Разрабатывается информационная система для сети из
12 медицинских клиник: запись пациентов на приём, электронная медицинская
карта (ЭМК), отчётность для контролирующих органов здравоохранения и модуль
администрирования/разграничения доступа.

Подробное описание кейса, анализ неопределённости модулей и обоснование
выбора модели процесса разработки — см. `docs/decisions/0001-process-model-choice.md`
и отчёт по ЛР1.

## Contributing

### Модель ветвления

Для проекта выбрана модель **Trunk-Based Development**: одна основная ветка
`main`, короткоживущие ветки `feature/*` (не более 1–2 дней), частая
интеграция через Pull Request.

**Обоснование выбора:** в отличие от GitFlow, Trunk-Based Development не
требует поддержки отдельной долгоживущей ветки `develop` и хорошо сочетается
с еженедельным циклом лабораторных работ курса — каждая неделя добавляет
небольшой, быстро интегрируемый инкремент (SRS, затем архитектура, затем код),
а не длинную серию параллельных релизов, для которой оправдан GitFlow. Модель
также закладывает основу для активной практики CI/CD, которая понадобится на
неделе 17.

Соглашение об именовании веток:

- `feature/<номер-задачи>-<краткое-описание>` — новая функциональность;
- `fix/<номер-задачи>-<краткое-описание>` — исправление дефекта.

Прямой push в `main` запрещён — только через Pull Request с минимум одним
approve от другого участника команды (см. branch protection rules).
